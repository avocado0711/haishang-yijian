# Demo 与路演脚本

## 3 分钟 Demo 视频

### 0:00–0:20 命题与用户

画面：顶栏「上服定制业务协作台」、业务类型切换。

旁白：这不是 C 端换装工具，而是给上服定制业务人员使用的需求解构、资源匹配与台账交接助手。

### 0:20–1:05 需求解构

操作：载入「私定演示：见客外套」，在右侧台账指出六维分组与审美标签报告。

旁白：客户原话被转成 14 个结构化字段，并按六维需求归档。每个字段明确区分已确认与待确认，AI 建议不会自动进入最终方案。

### 1:05–1:50 企业资源匹配

操作：进入设计图，选择「玄纹立领外套」，展开企业资产库，切到「案例」。

旁白：进入设计必须确认品类并至少确认 3 个设计相关字段。系统按品类和工作模式做硬约束，展示匹配标签、匹配理由和待复核差距；外套不会再匹配到衬衫，没有同品类资产时也会明确停止。

### 1:50–2:25 视觉提示词与版型

操作：查看「方案初稿」，展开提示词并切换成衣效果 / 工艺细节 / 上身穿搭三套；复制三套后进入版型，确认领型与衣长为需求派生结果。

旁白：方案初稿汇总风格、轮廓、面料、领型衣长、工艺、场景和亮点。提示词只使用已确认字段，企业基线只作为单独标注的参考；版型默认值、打样检查项和最终产品名称保持一致。

### 2:25–2:50 台账交接

操作：进入打样与交付，展开三套提示词台账，在「业务台账备注」填写一条待复核事项，再下载台账。

旁白：客户需求、方案初稿、三套提示词、业务备注、打样状态和操作留痕合并成同一份可上报台账。

### 2:50–3:00 边界与价值

旁白：Agent 只做辅助草稿，报价、定版、交期和生产仍由业务人员确认。

## 8 分钟决赛路演

| 时间 | 内容 |
| --- | --- |
| 0:00–1:00 | 业务痛点：感性需求、资源非结构化、方案难复用、台账依靠手工 |
| 1:00–3:30 | 私定案例完整演示：确认态需求、品类安全匹配、提示词、版型、台账 |
| 3:30–4:30 | 团体职业服案例：岗位适配、数量、抗皱面料和统一台账 |
| 4:30–5:40 | 技术架构：LLM 解构、规则约束、静态资产适配、可恢复降级 |
| 5:40–6:50 | 商业与产业价值：洽谈周期、复用率、新人上手、版本审计 |
| 6:50–7:30 | 落地路径：模拟数据 → 脱敏资产库 → 业务台账接入 |
| 7:30–8:00 | 团队与边界：人工决策、数据合规、后续里程碑 |

## 5 分钟答辩准备

- 为什么不是消费者自助工具？
- 如何避免大模型把建议误当确认？
- 匹配分如何计算，为什么不直接让模型自由推荐？
- 如何证明提示词和最终方案没有漂移？
- 系统接入真实业务后的权限、审计和隐私如何处理？
- 与通用 AI 绘图或通用 CRM 相比，差异化在哪里？
